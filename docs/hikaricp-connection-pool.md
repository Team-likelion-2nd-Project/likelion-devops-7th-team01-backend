# HikariCP 커넥션 풀 설정 근거 (M3-4)

## 설정값

| 항목 | 값 | 이유 |
|---|---|---|
| maximum-pool-size | 5 | db.t4g.micro의 max_connections(약 60~90개 추정)를 파드 여러 개가 나눠 쓸 것을 고려한 보수적 값 |
| minimum-idle | 2 | 매 요청마다 새 연결을 안 만들어도 되도록 최소한만 유지 |
| connection-timeout | 3000ms | 무한 대기 대신 빠르게 실패시켜 문제를 조기에 발견 |
| max-lifetime | 600000ms (10분) | 오래된 연결의 조용한 끊김 방지, 주기적 교체 |
| idle-timeout | 300000ms (5분) | 유휴 연결 정리 |

## 계산 근거

- db.t4g.micro(1GB RAM) 기준 MySQL max_connections는 대략 60~90개로 추정됨 (실제 RDS 파라미터 그룹 확인 필요)
- 파드가 최대 10개까지 늘어나는 경우를 가정해도 `5 × 10 = 50`으로 한도 안에 들어오도록 설계
- 정확한 최적값은 M9 부하테스트에서 실측 후 조정 예정 — 지금은 "DB를 다운시키지 않는 안전한 기본값"이 목표

## 검증

정원 10인 강의에 서로 다른 학생 20명 동시 요청 테스트로 검증 예정 (JWT 인증 적용 후 재검증 필요).
